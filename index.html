Phase 5 and Phase 6 / browser-run beta

AI Delivery Control Surface

This prototype turns your spec into one sane human-facing dashboard: feature intake, automatic versus gate-by-gate execution, workspace visibility, PR explanations, observability, and Codex-like versus Claude-like routing.

What is real here

The orchestration model is real: intake, phase ownership, approvals, logs, metrics, and generated PR copy. The runtime is still simulated locally in the browser, so live repo checkout, CI streaming, and actual PR creation remain backend follow-up work.

  • Feature request submission
  • Automatic and gate-by-gate modes
  • Task and workspace monitoring
  • PR summary, rationale, risk, migration notes
  • Phase 6 metrics and failure clusters

Execution mode

Automatic mode is active. The pipeline will run from intake through PR packaging unless it hits an exception.

Feature queue

Active requests stay visible so a human can jump between work without asking the pipeline to explain itself from scratch.

Feature intake

Submit the work in plain language. The pipeline turns it into architect, coding, verification, review, and PR packaging tasks.

Data is stored only in local browser storage for this prototype.

Task pipeline

Each phase shows the owner, rationale, and current status. Gate mode pauses on approval checkpoints. Automatic mode runs straight through.

Workspaces, diffs, and logs

Humans should be able to inspect where the work is happening, how large the change is, and the latest execution note without spelunking terminals.

Observability

Phase 6 makes the system measurable: throughput, pass rates, token spend, review time, and the hotspots where prompts or routing rules need adjustment.
